# 插件使用指南

SPlayer Atom 保留并迁移了 SPlayer-Next 的插件能力，可通过 Core 插件扩展**音源**（解析歌曲的播放地址）与**控制**（反向控制播放、插件设置和歌曲菜单）。不依赖 Desktop/Electron 专有接口、且只使用当前文档 API 的 SPlayer-Next 插件通常可以继续使用。本文面向最终用户，介绍如何安装、启用与管理插件。想自己写插件，见 [插件开发](/plugins/)。

## 打开插件管理

**设置 → 插件管理**。每个已安装插件以卡片展示：名称、版本、作者、运行状态与支持的音源。

## 安装插件

Web Control 只提供 **URL 导入**：粘贴一个指向 `.js` 脚本的 HTTPS 链接（如 GitHub / Gitee 的 raw 地址），由 Core 下载、校验并安装。这样浏览器不需要访问 Core 主机的本地文件选择器。

部分作者会以 `gz_` 前缀分发压缩脚本，Core 会**自动识别并解压**，无需额外操作。

## 启用 / 禁用 / 卸载

- 新安装的插件会**自动启用**。
- 在卡片上可随时启用或禁用插件；可同时启用多个插件（含多个音源），当多个插件支持同一音源时，由 Core 按优先级自动选用。
- 控制插件若声明了设置项，可在卡片上打开**设置**进行配置。
- **卸载**会删除脚本及其本地数据，且不可恢复。

状态徽章：**已就绪**（可用）、**加载中**、**错误**（卡片下方会显示原因）、**已禁用**。

## SPlayer-Next / LX 插件兼容

SPlayer Atom 的原生插件接口来自 SPlayer-Next 插件系统并已迁移到 Node Core；插件若只使用当前文档列出的 `splayer` API，可继续在 Atom 中运行。

Core 同时兼容 [lx-music-desktop](https://github.com/lyswhut/lx-music-desktop) 的 `user_api` 脚本，多数公开脚本可通过 raw URL 直接导入。若插件依赖 Atom 未实现的 API、Electron/DOM 或其它宿主专有能力，则可能无法加载。

## 常见问题

**导入后状态显示「错误」？**
查看卡片下方的错误信息，通常是脚本本身的语法 / 运行错误，或脚本声明的 API 级别高于当前版本（需等待应用升级）。

**插件崩溃会影响应用吗？**
不会。插件运行在独立沙箱中，崩溃会被隔离并自动恢复，不影响主程序。

**插件请求很慢？**
插件的网络请求会遵循系统代理，速度取决于目标接口与网络状况。
