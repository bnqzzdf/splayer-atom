## 1. 目标与参考

让用户更快找到目录内的音乐、辨认物理文件，并清楚理解显示顺序与播放范围。
保留 Core-owned、逐层浏览、扫描前可用的模型；不扩展成通用文件管理器。

参考依据：

- [Roon Folder Browser](https://blog.roonlabs.com/folder-browsing/) 将固定目录、递归播放、
  可选信息列、排序筛选、专辑/艺术家跳转和图片/PDF 阅读结合起来。
- [Roon ARC Folder Browser](https://blog.roonlabs.com/arc-folder-browsing-arrives/) 提供
  专辑、专辑艺术家、格式等排序，并保留文件名信息。不能据此假定任意物理目录都对应
  单一专辑或拥有可靠的艺术家、年份属性。
- [Roon 排序说明](https://help.roonlabs.com/portal/en/kb/articles/sorting) 区分显示排序与播放动作。
- [foobar2000 官方记录](https://www.foobar2000.org/changelog-mac) 提供 Album List、ReFacets、
  Library Search 等浏览组件；Atom 同样可由专辑、艺术家等现有页面承担深入的元数据浏览。

本方案采用三种基础排序和少量必要信息，不照搬全部高级音乐库筛选器。

## 3. 第一批：显示排序

### 3.1 选项和范围

| 显示选项 | 协议值  | 首次选择的方向 | 适用规则                                             |
| -------- | ------- | -------------- | ---------------------------------------------------- |
| 文件名   | `name`  | `asc`          | 默认；使用物理文件/目录名称自然排序，数字 2 在 10 前 |
| 修改时间 | `mtime` | `desc`         | 使用当前条目的文件系统修改时间，默认最新在前         |
| 曲目顺序 | `track` | `asc`          | 普通已扫描音频按碟号、轨号排列；其余规则见下文       |

三种模式均可切换升降序。首次进入且无偏好时保持现有 `name/asc`。
本批只改变普通目录的直接子项排序；首页根目录、固定目录和递归搜索结果不增加排序菜单。

共同规则：

1. 固定“文件夹 → 音频/容器 → 附属资料”分组；降序不反转分组。
2. 名称比较复用现有 Core 自然排序；相同排序键再以自然名称、精确路径确定顺序。
   名称比较相等时以精确路径升序收尾，不依赖 `readdir` 返回次序。
3. `mtime` 相同的条目按名称、路径升序排列；时间为 Unix 毫秒。
4. `track` 模式下，有有效轨号的普通音频按 `disc`（缺省 1）、`track` 排序。
   无有效轨号的音频和外层容器统一放在这一组之后，按名称升序排列；升降序不把未知项移到前面。
   同碟号、轨号以名称、路径升序收尾。本模式不推断专辑分组，混合专辑仍遵守该规则。
5. `track` 模式下，子目录和附属资料始终按名称升序排列；菜单说明“曲目顺序仅用于音频”。
6. CUE/SACD 在外层作为一个容器参与名称/修改时间排序；不为曲目排序预先展开容器。
   展开后的虚拟曲目始终保持现有容器顺序，不受外层升降序影响。
7. 不为未扫描音频补齐排序字段而探测媒体；扫描后通过正常 library revision 刷新排序。

修改时间指目录自身或文件自身的 `mtime`，不表示后代音乐的最近更新时间。
不递归计算目录大小、后代最新时间或目录“专辑年份”。暂不提供“最近添加”，也不使用
`mtime/ctime` 代替入库时间。

### 3.2 UI 与状态

在现有当前目录筛选、列表/网格切换附近增加“显示排序”下拉框和方向按钮；窄屏允许换行，
不增加侧边树。列表与网格共用同一排序结果，切换视图不重置排序。

- 默认排序偏好复用 Web settings 持久化，按 Web Control 保存；不加入 Core 音乐库设置。
- 路由/历史项保存当前 `sort/order`，刷新和前进后退恢复该导航项的排序；无参数时使用
  当前 Web 偏好。进入新子目录继承当前排序，不建立持久化的逐目录设置表。
- 筛选状态按目录保留在 Web 会话内；返回父目录时恢复该目录自己的筛选。
  子目录导航把返回目标写入父目录 history 项的 `focusPath`，返回时确定性定位刚离开的子目录。
  不维护逐目录像素滚动位置，也不为精确像素恢复增加额外状态机。
- 主动改变排序或筛选时清空分页和批量选择，从首屏重新加载；旧请求响应不能追加到新结果。
- “打开所在文件夹”对普通音频通过 Core 的 `focusPath` 定位真实文件；对 CUE/SACD
  定位并展开物理 `.cue/.iso` 容器，不再把虚拟分轨当成文件系统定位目标。
  显式目标定位优先于普通入口位置；若旧筛选排除了目标，清除该筛选以显示目标。

### 3.3 Core 合同与分页

在现有 browse 合同增加可选 `sort/order`，省略时为 `name/asc`，方向值为 `asc/desc`。
枚举及请求类型放在 `shared/types/folderBrowser.ts`，路由校验非法值；不增加第二套浏览 API。

Core 处理顺序：当前目录枚举 → canonical 关联和已有容器去重 → 当前目录筛选 →
分组排序 → focus 定位 → 分页。Web 不对已加载页自行排序。

- 复用枚举阶段已经读取的文件属性。目录、已扫描 Track、CUE/SACD 条目补充当前物理
  `mtime`；文件/容器补充当前物理 `size`。目录不暴露伪造的总容量。
- 属性放在 Folder 条目层，canonical Track 仍是音乐元数据权威；不为显示排序修改数据库 Track。
- 游标绑定目录身份、规范化筛选、排序及方向。条件不匹配拒绝续页；内容变化沿用
  `FOLDER_CURSOR_STALE`，Web 清空旧页后重新请求。
- 仅检查父目录 `mtime` 不足以判断新排序是否过期：修改文件内容可能改变文件时间而不改变
  父目录时间，扫描也可能改变轨号。利用本次已枚举的结果生成排序结果签名，覆盖有序条目身份及
  当前有效排序键，并复用 library revision 校验元数据更新；不新增全树 watcher 或持久化索引。
- 对稳定目录，前后翻页必须无重复、无遗漏。目录正在外部变更时允许刷新重取，不建立跨请求
  文件系统事务快照，也不以缓存整棵目录树保证分页。

## 4. 第一批：文件信息与操作语义

### 4.1 必要信息

- 已扫描音频保留歌曲标题，增加物理文件名；继续显示艺术家/专辑。
- 桌面紧凑展示碟/轨号、时长和格式/音质摘要；修改时间排序时展示可理解的时间值。
  大小、完整路径及其余属性可收进按需详情，不在首屏铺开所有列。
- 未扫描文件显示文件名、扩展名、大小，元数据未知时显示空值或“未扫描”，不显示伪造的 0 时长。
- 移动端优先标题/文件名和简短格式，额外属性按需查看；复用现有详情与格式化能力，
  不引入通用可拖拽列编辑器。
- 虚拟曲目的文件信息指向物理容器，不把 ISO/CUE 文件大小显示为单曲大小。

### 4.2 显示、筛选与播放

“显示排序”只影响浏览，不更改播放队列或目录播放策略：

- 整目录播放、接下来播放、加入队列和歌单继续复用 Core 的确定性解析：当前目录曲目优先，
  再按自然名称深度优先遍历子目录；当前目录内保留碟号/轨号/CUE 顺序规则。
- 目录主播放动作明确标示包含子目录；“仅当前目录”保留为现有子菜单。
- 当前目录筛选不改变整目录动作的范围；筛选激活时仍要让用户识别动作包含未显示项。
- “播放所选”等批量动作按提交时的可见列表顺序发送选中目标，Core 负责容器展开、去重及队列构建。
  展开 CUE/SACD 后，外层容器不再作为批量候选，避免容器与内部虚拟曲目重复选择。
- 不在第一批增加“按当前排序播放全部筛选结果”。后续若需要，由 Core 接收筛选/排序条件处理完整
  结果，不能只播放已加载页。

### 4.3 选择与搜索范围

- UI 只提供“全选 / 反选”，分页是内部实现细节。执行时按当前目录、当前筛选和当前排序遍历
  完整分页，再对全部可选音频/容器/展开曲目操作；排除目录和资料。
- 展开 CUE/SACD 时只选择内部虚拟曲目，不同时选择物理容器；折叠状态下容器仍可作为整体目标。
- 排序/筛选变化时清除选择，避免选中集合被静默改变。第一批不增加多目录递归批量选择。
- 消费现有搜索响应的 `truncated`：显示“搜索达到上限，请缩小范围”。这是搜索遍历预算达到上限，
  与 `nextCursor` 表示仍有下一页是不同状态；新查询清除旧状态，后续页出现截断时保留提示。

## 5. 第二批

第二批只保留三项明确增强，不再扩展新的排序维度或其他 Folder Browser 能力：

| 增强                  | 实施边界                                                                                         |
| --------------------- | ------------------------------------------------------------------------------------------------ |
| 当前子树递归搜索      | 复用现有搜索 API 和 DFS；根页搜索全部音乐目录，目录内搜索仅遍历当前目录及后代；继续限量、可取消  |
| 文件夹关联专辑/艺术家 | 只归纳当前目录直接媒体已有的可靠 canonical Track，不递归子目录、不额外扫描或查询；仅展示唯一关联 |
| 批量失败提示          | 复用现有 `count/failed/added`，只提示全部/部分失败及失败项数，不展示路径、内部 ID 或异常细节     |

当前目录筛选继续只处理直接子项，与递归搜索保持两个独立入口。目录内搜索只给现有
`/library/folders/search` 增加可选范围，不建立索引、目录树缓存或 watcher，也不借此重做全局搜索。

专辑/艺术家快捷入口位于文件夹级区域，不修改每首曲目的稳定行布局。关联计算直接复用当前 browse
已经取得的直接媒体 canonical 数据；有未扫描或过期的直接媒体时不显示关联。专辑出现第二个不同
canonical identity 后停止继续判断专辑，艺术家出现第二个不同名称后停止继续判断艺术家；两项都
已确定不唯一时可以结束归纳。子目录数量不参与计算，因此只有数百子目录而无直接音乐的大目录
不会产生递归或额外数据库压力。CUE/SACD 仅在已有新鲜 canonical 分轨时参与归纳。

失败提示不新增失败详情页、弹窗、重试状态机或结构化 failure 协议；Core 返回的失败路径只用于
判断失败数量，不直接展示给用户。

保持现有边界：不添加主机媒体删除、重命名、移动、复制、创建目录，不引入批量标签改写，
不为隐藏空目录递归扫描，不构建第二份音乐库索引、扫描器或播放 authority。
设置页的根目录管理保持添加/移除配置职责；移除配置不得删除用户音乐文件。

## 6. 实施顺序

1. **Core 合同与排序**：扩展共享类型、路由和现有服务，补齐物理属性、比较规则、游标校验；
   保留未传排序参数的兼容默认值。
2. **Web 控件与恢复**：扩展 client、settings、路由和 Folder 页面，完成排序切换、分页重置、
   过期请求丢弃、焦点和历史恢复；复用已有视图模式持久化。
3. **信息与范围提示**：补文件名和必要字段、播放范围、批量选择文案、搜索截断提示及现有语言包。
4. **验收与记录**：完成下述自动化和人工检查，在 Roadmap 分别更新开发状态与实际验收状态。

优先修改现有文件；只有排序比较/游标逻辑确实需要独立测试时再提取小型辅助模块。
不把本轮拆成新的 Folder service、store 或独立状态管理框架。

## 7. 验收标准

### 自动化

扩展已有 `core/services/folderBrowser.test.ts`、`core/atom/folderRoutes.test.ts`、
`src/core/folderBrowserClient.spec.ts` 和 Folder Web 测试，覆盖真实行为，避免只检查源码字符串。

| 场景           | 必须满足                                                                     |
| -------------- | ---------------------------------------------------------------------------- |
| 默认与自然排序 | 省略参数行为兼容；CD2/CD10、2/10 顺序正确；升降序保持分组                    |
| 修改时间       | 文件夹/音频/容器/资料使用当前物理时间；相同时间稳定排序；不递归读取后代      |
| 曲目排序       | 缺省碟号、缺失轨号、同轨号有明确次序；混合未扫描文件和容器不触发额外探测     |
| CUE/SACD       | 外层排序不反转展开曲序，不新增 backing 音频重复项                            |
| 分页与筛选     | 超过默认 200 和最大 500 单页限制的数据遍历完整；匹配项在首屏之外仍能找到     |
| 游标变化       | 更换排序/筛选/路径不能复用旧游标；文件时间或扫描元数据改变时拒绝过期页       |
| Web 请求竞争   | 快速切换排序或目录时旧响应不混入新列表；切换排序清除选择与旧页               |
| 导航与定位     | 返回父目录恢复排序/筛选/锚点；刷新恢复排序；focus 定位到排序后正确页         |
| 操作范围       | 整目录动作不继承显示筛选/排序；全选/反选覆盖当前筛选完整分页；容器不重复选择 |
| 搜索截断       | 截断与下一页状态分别呈现，新查询清除旧提示                                   |

实现期间运行相关测试；合并前执行 `pnpm typecheck`、`pnpm test`、`pnpm lint`、
`pnpm build:web` 和 `git diff --check`，同步文档时运行 `pnpm docs:build`。
本轮不修改 native/audio，除非实际依赖变更需要，否则不增加音频硬件或 Rust 全量重验。

### 人工与性能

2026-09-28 已完成当前真实音乐库和浏览器下的第一批功能验收：

- 名称、修改时间、曲目顺序及升降序符合预期；固定分组保持稳定，CUE/SACD 内部顺序不受外层排序影响。
