## Product rules that must survive context loss

The primary rule is:

> **SPlayer owns the architecture; Atom owns only the delta.**

For most product areas this means aggressive reuse of SPlayer UI, Track/queue/media stores, source resolution, player state, persistence, HTTP/WS/MCP, and upstream provider patterns.

Diretta is the deliberate exception at the audio-data boundary: fidelity requirements take precedence over reuse of SPlayer's normal `f32` playback pipeline.

### Mandatory Diretta Source Direct contract

A Diretta Source Direct path must never silently pass through SPlayer's normal `Resampler<f32>` / DSP path. It must preserve the source representation after only the unavoidable lossless codec decode/container layout work.

Strict invariants:

- original sample rate;
- original channel count;
- original effective PCM sample bits;
- no resampling;
- no channel remix/downmix;
- no float normalization step for integer direct PCM;
- no EQ/preamp;
- no ReplayGain/Normalization;
- no software volume below unity;
- no fade;
- no tempo/pitch processing;
- no re-encoding;
- native DSD must remain native DSD, never PCM/DoP fallback;
- unsupported exact Target formats fail explicitly;
- no silent fallback to the normal SPlayer audio path.

While Direct mode is selected/active, sample-altering controls are **rejected with an explicit `[Direct]` error** telling the user to exit Direct first. Do not silently exit Direct and do not silently apply the processing.

## Diretta Source Direct — current implementation state

### 1. SDK integration model

The Diretta Host SDK is C++, so the correct split is:

```text
Rust audio-engine
  -> very thin C ABI
  -> Atom-owned C++ bridge
  -> Diretta Host SDK 149
```

C++ is only an SDK adapter. Player orchestration, buffer ownership, ring state, source handling and lifecycle remain Rust-owned.

The real SDK is available at:

`/home/bnqzzdf/code/DirettaHostSDK_149`

Linux SDK archives are non-PIC. The proven NAPI/shared-object link solution is:

- statically bind libstdc++;
- final DSO link with `-Wl,-Bsymbolic`;
- keep libgcc dynamic;
- no helper process.

SDK-enabled release `audio-engine.node` has been built and actually loaded by Node. ELF checks showed no `TEXTREL` and no dynamic `libstdc++.so` dependency, preserving the single-address-space zero-copy design.

### 2. PCM Direct core

Atom-owned core: `native/audio-engine/src/direct_pcm.rs`.

Packed integer paths:

```text
WAV / FLAC packed S16/S32
  -> FFmpeg refcounted AVFrame slot
  -> exact AVFrame payload pointer
  -> DIRETTA::Sync::getNewStream()
```

This is true zero-copy after codec decode.

Planar integer paths:

```text
ALAC / WavPack / APE S16P/S32P
  -> one integer-only planar -> interleaved repack
  -> reused stable slot buffer
  -> exact same repack pointer to Diretta callback
```

This is still bit-perfect Source Direct: only memory layout changes; sample values do not.

Current evidence includes WAV16/24/32, FLAC24, ALAC16/24, WavPack16/24/32 and real APE16. APE24/32 share the same proven generic S32P path but do not yet have codec-specific local fixtures because the installed FFmpeg has no APE encoder.

Rare APE `u8p` is still strict-unsupported because unsigned->signed PCM8 is reversible but not bit-identical.

### 3. Native DSD core

Atom-owned core: `native/audio-engine/src/direct_dsd.rs`.

- Parses DSF/DFF directly; no FFmpeg PCM decode.
- DSF preserves LSB-first source bits.
- DFF preserves MSB-first source bits.
- Performs only the lossless L4R4 memory-layout repack required for Diretta `DSD_SIZ_32`.
- Exact SDK format is `FMT_DSD1 | FMT_DSD_SIZ_32 | FMT_DSD_BIG | source LSB/MSB`.
- No bit-reverse compatibility fallback, no opposite-order retry, no DoP, no DSD->PCM.
- Synthetic bit-pattern tests and real 10 ms DSF/DFF assets have both passed.

### 4. Real-time callback contract

The old `SyncBuffer::setStream + memcpy` prototype has been removed from the production hot path.

The C++ bridge now derives from `DIRETTA::Sync` and uses `getNewStream()` pull mode.

The real-time callback is guarded so it cannot contain:

- PCM/DSD `memcpy`;
- heap allocation/resize;
- mutex work;
- discovery;
- format negotiation;
- logging/business logic.

It only releases the previous in-flight block, borrows the next stable pointer/size and assigns `stream.Data.P / stream.Size`.

### 5. Direct Lifecycle Gate — automated proof complete

Direct load branches **before normal playback runtime construction**. The Direct path does not create SPlayer `Shared`, player resampler/DSP, normal decoder thread or normal `PlaybackHandle`.

Direct lifecycle now participates in the same SPlayer `InnerPlayer` state owner and supports:

- load;
- play;
- pause;
- stop;
- position/status/ended/source-error reporting;
- exact seek;
- explicit output-mode switching.

Important seek design:

- Direct seek does not destroy/reconnect the Diretta connection;
- it pauses/releases in-flight data, repositions the producer, refills the **same ring**, then resumes;
- connection pointer, callback context and ring address remain unchanged;
- packed PCM seek preserves zero-copy pointer offset semantics;
- planar PCM remains integer-only repack;
- DSF/DFF seek remains native-bit exact.

Architecture tests explicitly forbid the Direct NAPI load/seek branch from invoking normal `Shared`, `AudioOutput`, `prepare/start/resume_decode`, normal commit or normal fallback load paths.

### 6. Same-format connection reuse + true staged gapless core

This is no longer just "connection reuse".

Native staging can prepare a next local/seekable source on the current Direct producer and, if the Diretta **wire format** is identical, cross the boundary without reconnecting or inserting data.

PCM compatibility key:

- sample rate;
- channels;
- storage width.

Codec/container/memory-layout differences do not force reconnect. Example: packed FLAC PCM32/96k -> planar ALAC/WavPack PCM32/96k is compatible.

DSD compatibility key:

- DSD bit rate;
- channels;
- source LSB/MSB wire order.

Automated tests prove:

- staged PCM handoff is sample-contiguous;
- staged DSD handoff is bit-contiguous;
- callback context remains unchanged;
- incompatible format is rejected before replacing the current source/ring;
- no silence is inserted to hide an underrun.

### 7. Renderer/queue gapless integration

Renderer/native coordination uses a monotonically generated staging `generation`.

Flow:

```text
renderer resolves next candidate
  -> native stageDirectNext(source, duration, generation)
  -> native marks exact audio boundary with generation
  -> native emits directTrackBoundary(duration, generation)
  -> renderer validates queue candidate + generation
  -> renderer commits SPlayer media/queue/metadata state
  -> NO normal player.load()
```

An Atom-owned static architecture test (`src/core/player/directGapless.test.ts`) forbids the Direct boundary/commit path from reloading or stopping audio.

Playback semantics guarded before staging:

- repeat-one: do not stage next;
- auto-close waiting for current song end: do not stage next;
- CUE ranges: not staged yet;
- staging itself still accepts only local seekable sources, but Qobuz/TIDAL remote inputs are now prepared into local cache/process-lifetime materialized files before staging.

Local metadata/lyrics are preserved by a read-only metadata probe. `probe_metadata()` reuses `prepare_decode()` only for source open/tags/cover/lyrics metadata; **the normal f32 resamplers are created later in `start_prepared_decode()`, so metadata probing does not enter the normal playback path.**
