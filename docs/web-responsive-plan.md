# Web Control 手机与平板响应式适配实施规格

更新：2026-09-21。本文替代此前版本的工作包、尺寸测量设计和验收流程。

状态（当前代码，2026-09-23）：响应式主布局、导航抽屉、手机单行播放栏、列表、
完整播放器、设置和弹窗适配已实现；已批准的两项交互删除已完成。
手机播放栏和底部定位在后续实现中调整为单行、固定视口底端；本文第 3/5 节相关
描述已按当前代码更新。代表尺寸、真机和 E01～E15 的完整验收尚无记录，
由 [atom-roadmap.md](./atom-roadmap.md) 追踪。
执行者先读 `AGENTS.md` 与 [开发约定](./atom-development.md)。

## 1. 已确定的范围和取舍

### 1.1 产品要求

适配手机、平板浏览器，消除实际出现的文字、菜单、控件重叠。采用同一 Web Control、
同一路由和现有 Core 契约；以最小改动、最简实现、稳定和性能为准则。
正式入口仍是 `src/main.ts` 的 `mountWebControl()`，不以 `/debug` 诊断页替代。

| 项目                     | 结论                 | 实施要求                                                                             |
| ------------------------ | -------------------- | ------------------------------------------------------------------------------------ |
| 播放队列拖拽排序         | 用户批准删除；已完成 | 保留正常点歌、滚动、删除、清空、定位当前项；不重新引入拖动、长按、自动滚动及专用状态 |
| 歌曲行重复 dblclick 播放 | 用户批准删除；已完成 | 保留 click 原处理，不添加防抖、计时器或点击次数判断；其他组件的双击不在删除范围      |
| 自动沉浸模式             | 用户明确要求保留     | 保留设置入口、开关、现有 3000ms 超时、控制栏/鼠标隐藏和恢复行为                      |
| 其余功能                 | 保留                 | 可移动入口或改变排列，不改业务含义、条件、参数和结果                                 |
| Android 同源项目         | 作为主要移动布局参考 | 借鉴排列和信息层级，不迁入平台桥接、业务实现和新增手势                               |

本次删除不包括侧栏自定义排序、歌曲列表按字段排序、随机/循环播放，也不删除 Core 队列
命令或协议。不得扩大成“清理所有排序/双击/计时器”。

### 1.2 功能不变的具体含义

适配后的按钮、菜单、表单继续调用原处理函数，保留曲目/队列索引、来源、PlaybackContext、
音质、设备 ID、时间单位和设置值。原有可见/禁用条件、确认/取消、加载与错误提示保持。
功能等价以两项批准删除后的行为为基线，不把被删除的交互列为必须恢复的功能。

- 纯布局变化不切歌、不重排队列、不选择输出、不保存业务设置或覆盖桌面显示偏好。
- 入口收入菜单后仍可触摸访问，不用隐藏功能换取布局不重叠。
- 原有插件动态菜单和设置 schema 继续使用；不硬编码移动端功能子集。
- 不改播放策略、输出限制、歌词时间/解析、缓存、预加载、下载、统计、登录或插件逻辑。
- 现有代码如与已接受需求冲突，单独记录；不在适配过程中顺手修无关业务。

### 1.3 本版取消的额外设计

- 取消强制 ResizeObserver 测量底栏和 B/R/O 共享占位体系；窄屏主内容独立滚动，
  为固定底栏保留简单空间。
- 取消“所有组件实例永不重建”的硬要求；保留现有状态所有权，不复制业务实例或初始化。
- 取消旋转后精确恢复首个可见项目的要求；不主动重置页面，不新增滚动锚点算法。
- 不预先开发多级菜单页面、返回栈或通用手势系统；优先调整现有组件。
- 不建立全量 HTTP/WS 录制对照、自动计数所有监听器或专用测试 Core 的新工程。
- 不要求几十次重复跨断点，也不把所有设备、主题、语言、业务状态做组合遍历。

这些取消不降低“功能可达、布局可用、没有新增业务副作用”的要求，改变的是实现和验证方法。

## 2. 实施边界

| 区域                                                  | 允许内容                                                                 |
| ----------------------------------------------------- | ------------------------------------------------------------------------ |
| `src/layouts/`、`src/pages/`、相关 Vue 组件           | 模板、样式、必要的展示 prop/本地开关、原处理函数的入口接线               |
| `src/styles/`、`src/web/runtime.css`、`index.html`    | 响应式、安全区、视口及必要的焦点样式                                     |
| `useFloatingPlayerBar.ts`                             | 仅使窄屏不再套用桌面浮动栏补偿；保留已有调用方式，按实际需要作局部修正   |
| 可选 `useResponsiveLayout.ts`                         | 多个组件确需 JS 结构判断时共享只读媒体查询；不为纯 CSS 排版新增它        |
| `useImmersiveMode.ts`                                 | 仅在触摸适配需要时接入原显示恢复入口，不改设置和超时，不建立新的手势判断 |
| `OutputDeviceSelector.vue`、`CoreDirectoryPicker.vue` | 宽高、排列、文本和点击区域；不改请求/选择逻辑                            |
| i18n、自动生成声明                                    | 补必要文案；生成文件只接受现有工具产生的必要差异                         |

以下只读：`core/`、`native/`、`shared/`、`src/core/`、`src/services/`、`src/apis/`、
`src/actions/`、`src/stores/`、设置 schema/categories/绑定、歌词 engine、虚拟列表算法、
`useTrackMenu`、`useMultiSelect`、`useQueuePanel` 等业务 composable。
`.vue` 内的业务代码受相同约束。已完成的删除及注释清理保留，不借本次适配继续扩大删除。

不新增框架、依赖、移动路由树、播放器业务实现、持久化布局 store、Core 连接或轮询。
不导入 Android bridge/native 代码，不使用 UA/品牌识别，不限制浏览器缩放，不新增滑动切歌。
不以 `overflow-x: hidden` 掩盖被裁掉的内容，不全站缩放或堆叠 `!important`。

实施时先检查实际 CSS 和组件能力。新增抽象、兼容层或防护必须有本次任务中可复现的问题，
不能仅以“以后可能需要”为理由。若必须改变业务行为，先说明具体问题，不自行扩大范围。

保留原 RouterView/KeepAlive、路由 key 和现有数据持有者。不要同时挂两套手机/桌面业务组件；
只含展示的外壳可以按需要切换，不为维持其组件身份而写节点搬移/保活框架。
切换外壳若确实造成数据重复加载、输入丢失或输出提示重置，局部调整该组件的状态位置。

## 3. 页面布局与逐组件要求

### 3.1 断点与基本尺寸

| 宽度            | 布局                                                               |
| --------------- | ------------------------------------------------------------------ |
| `<768px`        | 手机：完整导航收进抽屉，内容单列，紧凑播放栏，设置分类与内容分层   |
| `768px～1279px` | 平板：保留现有 64/240px 侧栏偏好；内容按容器换行，使用非手机播放栏 |
| `>=1280px`      | 桌面：保留现有三种布局和用户侧栏偏好                               |

统一使用 768/1280px 的媒体查询。高度不足 500px 时只通过 CSS 缩小封面、放开必要滚动，
不新增 JS 设备模式。触摸目标可用 `(any-pointer: coarse)`/`(hover: none)` 样式，
鼠标和触摸并存时两者均可用。

手机页面横向留白起始值 12px，平板 16px，间距以 8/12/16px 为主；独立图标按钮及菜单行
触摸区至少 44px，输入文字 16px，普通正文约 14px、辅助文字至少 12px。
这些是初始实现值，不要求所有组件改造成统一尺寸系统；保留主题、图标和用户字体。

### 3.2 主布局与底栏占位

负责组件：`MainLayout.vue`、`useFloatingPlayerBar.ts`、相关页面/列表调用方。

1. 窄屏应用外框使用 Flex，顶部导航和可伸缩主内容在外框中；底部播放栏固定在
   当前视口底端，内容区域独立滚动，不随歌曲列表滚走。
2. 主内容 `min-width: 0; min-height: 0`；外框使用 `100dvh` 并保留 `100vh` 回退，
   安全区用 CSS `env(safe-area-inset-*)`；需要时补 `viewport-fit=cover`。
3. 窄屏去掉桌面的 left 偏移、固定 80px 底栏高度和 `mb-20` 补偿；`main`
   使用 `pb-16` 留白，底栏另用 `env(safe-area-inset-bottom)` 贴合视口。
4. `SongList`、`DownloadList` 窄屏只保留普通尾部留白；`CoverList` 保留调用方
   普通留白，不再加浮动栏高度；`Home`、`Stats` 同样停用窄屏浮动补偿。
5. `useFloatingPlayerBar` 的有效浮动状态只用于宽屏；不回写 `appearance.layoutMode`。
   桌面的现有补偿继续使用，只有复现末项遮挡才作局部修复，不顺带全面迁移桌面布局。
6. 没有当前曲目也显示底栏和输出入口。空状态、短列表和长列表都能看到最后一项。

不新建尺寸测量服务、共享 inset 状态或每行观察器。已有 `CoverList` 的容器测量照常保留，
上述限制不要求拆除已有且必要的实现。

### 3.3 导航与搜索

负责组件：`SideBar`、`NavHeader`、`NavSearch`、`NavUser`、已有 `SDrawer`。

- 手机导航抽屉宽 `min(320px, 100vw - 24px)`；复用原 menuItems/onSelect、分组、歌单、
  徽标、创建和自定义入口。选择项目后关闭抽屉；关闭本身不导航。
- 平板保留用户已保存的侧栏折叠宽度；手机导航使用抽屉，不覆盖保存的折叠偏好。
- 顶栏最小高 56px；菜单、返回、可截断标题、搜索、账户、更多。账户复用原 NavUser。
  前进、主题、界面缩放、设置可收入更多，继续调用原处理函数。
- 搜索继续使用 NavSearch；窄屏对话框近全屏显示，保留历史、建议、链接识别和来源选择。
- 侧栏原右键操作提供明确可点的更多入口；复用原菜单项，不建立第二份配置。

抽屉采用现有 Reka/SDrawer 的焦点和模态能力。仅为此页面确有需要时增加小的展示 prop，
不预先扩展 inline/bottom 多形态抽屉框架。

### 3.4 紧凑播放栏、队列和工具

负责组件：`PlayerBar`、`PlayerControls`、`Toolbar`、`TrackInfo`、`PlayerTimeInfo`、
`QueuePopover`、`OutputDeviceSelector`。

- 手机为 56px 单行：紧凑封面与曲名/艺人、输出、播放暂停、下一首和队列；
  细进度条贴在顶沿，其余操作沿用 Toolbar 和曲目菜单。平板使用非手机播放栏。
- 保留进度滑块；轨道可细，拖动区域至少 24px 高。时间显示和原时间格式切换可在控制面板内。
- 上一首、随机/顺序/心动/FM、循环、收藏、曲目菜单、音量、音质和工具均保留。
  优先复用已有控件，在原 Toolbar/菜单中重排；不复制其业务分支。
- 输出入口和首次选择提示仍可用，未播放时也能选输出；不按设备名自行推断 Direct 状态。
- 触摸音量面板使用明确的打开入口，面板中保留原滑块和独立静音操作；打开面板不调用静音。
  桌面既有操作保持，不新增事件识别或防抖。
- 队列使用现有 QueuePopover；先调整 Popover 的宽高、滚动和位置。普通面板能满足需求时，
  不为参考 Android 外观另写可拖动底部面板。清空确认、重复曲目索引和关闭语义保留。
- 队列没有拖拽排序，不添加长按/移动阈值/点击拦截等替代实现。

### 3.5 完整播放器和自动沉浸

负责组件：`FullPlayer/index.vue`、`PlayerCover`、`PlayerData`、`LyricActions`、`QueuePanel`。

- 手机纵向排列封面、歌曲信息、歌词/队列及控制；平板/横屏有空间时采用左右布局。
  去掉当前控制区 360px 最小宽度，封面同时受可用宽高约束。低高度时缩小封面并允许内容滚动。
- 保留 showLyric/fullQueueOpen/封面布局/居中等已有语义和所有入口，不改设置值来适应尺寸。
- 收藏、评论、加入歌单、下载音质、全屏、收起、时间格式和歌词工具仍可访问。
- 歌词点击沿用 handleLyricSeek 的毫秒参数和原 seek/play 顺序；两种引擎及其时间来源保持。
- 自动沉浸明确保留：原开关、3000ms 超时、鼠标静止/离开时隐藏、移动恢复、控制栏悬停
  保持可见。与它相关的歌词工具和背景显示条件不更改。
- 手机如需唤醒，通过主体的普通触摸事件调用现有显示恢复函数即可。按钮/歌词继续原动作；
  不增加“首击拦截”、手势遮罩、长按判断或单独的触摸状态机。
- 保留现有显示/隐藏生命周期；不增加歌词实例、播放时钟或 RAF 循环。

### 3.6 列表、卡片与业务页面

负责组件：`SongList`、`CoverList`、`CoverCard`、`DownloadList`、各 `pages/*.vue`。

- SongList 继续使用 88px 虚拟行高（76px 卡片＋12px 间隔）。窄屏将横向列排成曲名、
  艺人/专辑和辅助信息，保留原启用的序号、时长、大小、音质及艺人/专辑跳转。
- 标题省略或有限行数换行；较长说明、路径和设备名称在详情/面板中换行。先利用现有详情，
  不为每个省略文本建立专用展开组件。
- 正常点行播放、批量模式点行选择，子按钮保留原 `.stop`。不恢复重复 dblclick，不增加防抖。
- 批量模式、全选/反选、排序字段、收藏、下载、删除及插件菜单保留。工具栏允许换行。
- QueuePopover/QueuePanel 保持 56/72px 行高；触摸环境下删除入口可见。
- CoverList 复用现有容器列数和虚拟化；手机 `minSize` 可用 128px、gap 12px，实际列数由
  容器决定。不要同时保留独立的一套手机网格算法。
- 首页固定 4/3 列改为自适应；详情头部窄屏纵排；搜索来源/筛选区换行；文件夹树使用现有
  抽屉或展开区域；统计图确有需要时局部横向滚动。其他页面按相同组件处理。
- 不主动清空选择、查询或滚动位置；旋转允许正常重排，不要求恢复相同像素或第一项。
  不修改 SVirtualList 的算法，也不把虚拟列表改成全量渲染。

### 3.7 设置与通用弹层

负责组件：`SettingsDialog/Content/Item/Menu/Search`、设置 custom 组件、`modals/`、UI 浮层。

- 手机设置近全屏显示，分类与内容分层；平板能放下时继续左右布局。使用原 activeId、搜索、
  高亮和输入状态；复杂设置项说明在上、控件在下，开关可同排。
- schema、可见/禁用、子项条件、绑定、取值范围、确认和保存时机均不变。
- 所有 custom 设置、登录、评论、歌单、标签编辑、插件详情、路径选择和引导页面都检查，
  不只修改外框。主机路径仍指向 Core 文件系统。
- 常规弹窗宽度不超过视口减 24px，内容可滚动；搜索和设置可显式采用近全屏布局。
  短确认框保留紧凑形式；关闭/确认可达。
- 多级菜单先用现有 Reka 的点击、避碰、限宽限高和滚动能力。触摸子菜单不可用时，只修
  具体入口；不默认增加同宽子页面、返回栈或新的菜单数据结构。
- 继续使用已有焦点管理、Escape 和关闭回焦，不自建模态层管理器。
- 软键盘优先依靠浏览器与可滚动表单；真实设备出现遮挡时再局部修正。不提前建立
  VisualViewport 兼容管理器，不为假设中的键盘行为增加监听。

## 5. 可分派的实施工作包

以下是文件责任划分，不要求启动固定数量的 agent，也不要求每包交付多份报告。
执行前记录 HEAD 和相关文件已有差异。已完成的交互删除及用户的其他改动必须保留，不能覆盖。
同一共享文件只由一个执行者修改；跨文件接口需求交给该文件负责人，避免并行互相重写。

依赖：先完成 C1 的主布局/公共浮层，C2/C3/C4 可按文件所有权独立实施，最后 C5 集成。
每包均需对照第 2/3 节；下面列明具体文件、步骤、交付与对应 E 验收项。

### C1：主外框、导航和必要公共样式

文件：`MainLayout.vue`、`global.css`、`runtime.css`、`index.html`、`useFloatingPlayerBar.ts`；
`components/layout/*`、必要的 `SDialog/SDrawer/SPopover/SDropdownMenu/SContextMenu/SSelect/STabs`。
只有确有 JS 分支需要时增加 `useResponsiveLayout.ts`，供下游读取 `<768`/`<1280` 等少量布尔值。

步骤：

1. 固定 768/1280px 查询；完成第 3.2 节视口底端固定栏与窄屏独立滚动，保留宽屏三种布局。
2. 侧栏转抽屉/紧凑导航；沿用原菜单来源、onSelect 和持久化偏好，不改 sidebarNav 的路由数据。
3. 顶栏按钮与搜索/账户入口重排；公共弹层只增加限宽限高、必要的全屏展示选项。
4. 共享组件扩展保持默认行为兼容；不要批量改动未受影响的 UI 组件。
5. 向 C2/C3/C4 说明实际采用的断点读取方式、有效浮动状态和展示 prop，避免重复实现。

交付：可工作的主外框、简短接口说明及手机/桌面截图。检查 E01～E04、E07、E13。

### C2：播放栏、完整播放器与队列

文件：`components/player/` 的外层 Vue 组件、`list/QueuePopover.vue`、
`web/OutputDeviceSelector.vue`；`useImmersiveMode.ts` 仅允许必要的展示事件接入。
歌词 engine/时间服务只读；业务弹窗内容样式归 C4。

步骤：

1. 完成第 3.4 节手机单行紧凑播放栏；复用原 Toolbar 分支与输出提示状态。
2. 确认所有原播放工具有位置，输出/队列入口常显；Direct/远端输出禁用条件原样接入。
3. 调整完整播放器纵横布局，保留歌词切换、队列、评论/下载/收藏和歌词工具。
4. 自动沉浸按第 3.5 节保留并适配触摸；不扩展成新交互系统。
5. 队列继续使用现有浮层和虚拟行高，确保已删除拖拽不会恢复。

交付：手机/横屏播放器截图，移动过的入口及对应 handler 简表。检查 E03、E05～E09、E13。

### C3：列表和业务页面

文件：`list/SongList/CoverList/CoverCard/DownloadList.vue`；
`pages/Home/Songs/Liked/History/Daily/Cloud/Download/Collection/Artist/LocalList/Favorites/Search/Folders/Stats.vue`；
`pages/Streaming/*`、`components/stats/*`、`components/library/FolderManager.vue`。

步骤：

1. 完成第 3.6 节列表/网格排列，保留 88px 等原虚拟行高和现有算法。
2. 接入 C1 的窄屏有效布局：移除多余底栏补偿，保留普通尾部留白。
3. 详情页头部、搜索筛选、批量工具栏换行；菜单复用原 actions/composable。
4. 目录树按需收起；首页/统计/流媒体使用容器自适应，保留所有来源、筛选和页签。
5. 按下面的页面清单逐组打开检查；共用组件已验证的行为不必在每个页面重复写测试。

交付：各页面组检查结果、实际移动的操作入口。检查 E02～E04、E06、E10、E12、E13。

### C4：设置、业务弹窗与引导

文件：`components/settings/*` 及 `custom/*`、`components/modals/*`、
`pages/Onboarding.vue`、`components/onboarding/*`、`web/CoreDirectoryPicker.vue`。
设置 schema/categories/binding 只读；公共浮层改动交给 C1。

步骤：

1. 设置分类/内容分层，控件上下排列，复用原 activeId、搜索高亮、输入和保存流程。
2. 遍历所有现有分类及 custom 组件，修长路径、设备列表、插件表单等真实溢出。
3. 检查登录、评论、歌单、标签、音频工具和其他业务弹窗；关闭、取消、确认可达。
4. 引导顺序、跳过、保存语义不变，软键盘只针对复现问题局部处理。

交付：设置及弹窗覆盖记录、代表性长表单截图。检查 E02、E04、E07、E11～E13。

### C5：集成与收口

由主 agent 或指定执行者完成，不另设强制独立审计项目。

1. 合并展示接口和必要 i18n，检查没有重复断点、重复业务实例或已批准删除功能的回流。
2. 对照页面清单和移动过的入口检查功能可达；检查三种桌面布局和用户偏好仍有效。
3. 跑第 6/7 节规定的验证；记录具体未验证设备或已有失败，修复本次引入的问题。
4. 审阅实际差异：新增代码应能对应真实布局问题，不留下未用抽象、防护或测试框架。

交付：补丁、一个简短验收记录和必要截图/命令结果。检查 E01～E15，不自动提交或部署。

## 6. 必要验收

### 6.1 代表尺寸与环境

| 视口（CSS px） | 检查范围                                               |
| -------------- | ------------------------------------------------------ |
| 390×844        | 页面清单与主要操作的手机验收，作为窄屏主样本           |
| 320×568        | 导航、播放栏、长曲名列表、设置和典型弹窗的最窄布局检查 |
| 820×1180       | 平板导航、列表、播放器、设置                           |
| 844×390        | 横屏低高度下播放器、列表、弹窗可滚动且能关闭           |
| 1440×900       | 桌面三种布局、折叠/展开及代表性操作回归                |

在打开的页面/设置中跨过 768/1280px 并恢复一次；中英文、深浅/图片主题在代表页面检查，
不与全部路由和尺寸做组合遍历。浏览器缩放一次检查可读性即可，不构造专用缩放压力测试。

用实际可用的桌面浏览器和手机验证；移动端优先 iOS Safari/Android Chrome。
记录实际测过的设备。设备模拟可检查布局，不能声称已经验证真机键盘、安全区和触摸。
缺少某设备时明确“该设备未验证”，不要求先采购或建立完整设备实验室；正式宣称某平台
适配完成前，应补该平台代表真机检查。

测试数据使用现有开发数据或已有 fixture：至少有长中英文曲名、空队列/未选输出、普通队列、
有歌词/无歌词、长表单。虚拟列表用现有足够滚动的列表验证，只有改动虚拟行为或出现性能
回归时才扩大数据量。不为本次适配新建所有音源/账号/插件状态的完整模拟系统。
破坏性操作用隔离测试数据或现有 mock，不在用户真实音乐库执行删除/清空验收。

### 6.2 验收条目

以下是本次差异的检查单，不要求每项新建自动化测试或仪器。未改变的逻辑以代码复用审查
和已有测试为主；改动了事件接线时，检查相应操作的真实目标、参数和次数。

| ID  | 操作                                                       | 通过条件                                                                                        |
| --- | ---------------------------------------------------------- | ----------------------------------------------------------------------------------------------- |
| E01 | 审阅差异                                                   | 未改只读业务区域；既有改动保留；不恢复队列拖拽或重复双击；自动沉浸保留                          |
| E02 | 打开页面清单及长文本样本                                   | 无文字/按钮重叠和必需控件裁切；整页无意外横向滚动，允许图表/标签局部滚动                        |
| E03 | 空/有曲目，短/长列表滚到末尾                               | 底栏常驻、输出可用；末项及其操作可见，窄屏没有额外一整栏的重复留白                              |
| E04 | 跨断点后恢复、设置中输入后旋转                             | 路由/查询/选择/未提交输入及保存偏好保持；不主动切歌/选输出/保存；不要求像素级滚动一致           |
| E05 | 播放暂停、上一首/下一首、随机/循环及实际移动的特殊模式入口 | 仍调用原 handler 和原条件；FM/心动等分支未被简化；一次正常操作不因接线重复调用                  |
| E06 | 点队列曲目、删除、清空取消/确认                            | 索引正确、删除不触发行播放、取消不清空、确认沿用原链；无拖拽排序入口或专用事件                  |
| E07 | 打开菜单/二级菜单/输出/典型长弹窗                          | 内容可触摸访问和滚到末项，关闭/确认可达，原禁用/动态项存在，既有模态焦点行为可用                |
| E08 | 未选输出进入、打开音量、静音恢复、受限输出状态             | 输出提示/选择条件保持；打开面板不静音；原音量恢复值和 Direct/远端禁用保持，不增加处理命令       |
| E09 | 展开播放器、歌词/队列切换、进度与自动沉浸                  | 原入口/seek 参数/歌词行为保持；沉浸开关和约 3 秒隐藏/鼠标恢复有效，触摸可恢复操作，无新手势系统 |
| E10 | 列表首中末、封面网格改变宽度、批量操作                     | 无虚拟行重叠/空洞/错项；原排序/选择/来源/菜单保持；子按钮仍独立执行；不转全量 DOM               |
| E11 | 设置分类、搜索定位、修改取消/确认；引导/登录代表弹窗       | 设置项未减少，绑定/禁用/确认/保存时机不变，输入和步骤未因布局丢失                               |
| E12 | 真机搜索/长表单唤起键盘、横屏                              | 输入及关闭/确认可到达，收键盘后布局可用；缺真机则记录未验证，不冒充通过                         |
| E13 | 桌面三种布局、代表页面主题/语言                            | 桌面功能和偏好保持；无此次引入的挤压、隐藏入口或失效样式                                        |
| E14 | 检查新增运行时代码；隐藏/恢复播放器一次                    | 不增加播放连接、轮询、每行监听或高频工作；沿用原可见性生命周期，不为审计建立新计数系统          |
| E15 | 执行受影响检查                                             | 第 7 节必跑检查成功，相关已有测试通过；失败说明是否为基线问题及其影响                           |

必要操作可复用下面三组短步骤，无需额外记录每条 HTTP/WS：

1. **队列**：用 `[A, B, A, C]` 验证删除第二个 A 按索引操作；点 C 播放；清空取消/确认。
   普通滚动与点歌保留，不测试“消除全部误点击”，不为长按/拖动创建新拦截测试。
2. **输出/音量/设置**：未选输出时打开入口；可处理状态设音量 0.37，打开音量面板不改值，
   静音再恢复仍为 0.37；用已有受限输出状态检查禁用；设置改值取消/确认各一次。
3. **播放器/布局**：播放歌曲展开完整播放器，开/关歌词与队列，拖动进度；检查自动沉浸开关，
   静止约 3 秒后移动恢复；旋转并返回桌面，确认播放及显示偏好未被布局改变。

## 7. 验证与交接要求

每包先对改动文件做定向 lint/必要检查。集成时执行：

```bash
pnpm typecheck:web
pnpm build:web
pnpm exec eslint <本次修改的前端文件>
git diff --check
```

相关已有测试按改动选择：公共组件影响较广时跑 `pnpm test:web`；涉及播放器按钮、输出禁用
等展示接线时，运行对应的 `src/core/player/*.test.ts`（如 directUi/coreControlCommands）。
这些 `.test.ts` 使用仓库既有 tsx/Node 测试入口，不能以 Vitest `.spec.ts` 结果替代。
没有改变 Core/native 时不强制整个 `test:node` 或 native 构建。必要时扩大测试范围，
不为“保险”重复执行已经通过且未受新改动影响的检查。

只对本次实际改变、存在明确行为风险且现有测试未覆盖的接线补少量测试。纯 CSS、已删除
交互不要求配套测试框架；不写只断言 class 名的镜像测试，不降低已有测试要求以掩盖回归。
修改文档时做格式和 `pnpm docs:build` 检查；不在每个代码工作包重复构建文档。

交接只需一份简短记录：

- 修改文件、实际解决的布局问题，以及新增展示接口（如有）。
- 移动过的功能入口及原 handler/条件是否保持。
- E01～E15 中相关项的结果、实际设备/尺寸、必要截图和命令结果。
- 已有失败、未验证设备、未完成项；不用多份模板重复记录，不强制 call-traces 目录。

完成条件：相关验收通过，页面与原操作可达，没有新增业务副作用；无法验证的环境明确披露。
不能把截图检查写成真机验收，也不能把未实现功能写成通过。提交、合并、发布按用户授权执行。

可复制给子 agent 的任务：

```text
执行 docs/web-responsive-plan.md 的 C<n>，遵守 AGENTS.md 及方案第 1～3/6～7 节。
只修改该包负责的文件；先保留任务开始时已有差异，跨文件需求交给所属负责人。
按该包步骤实施，复用原 handler/条件/参数。自动沉浸保留，队列拖拽和重复双击不得恢复。
优先 CSS/现有组件；不要新增测量体系、手势防护、滚动恢复、通用兼容层或全量测试工程。
遇到真实阻塞，说明最小解决办法；不要自行删功能或改 Core/store/settings schema。
交付改动说明、相关 E 项结果、实际检查命令和未验证项；不自行提交或部署。
```
